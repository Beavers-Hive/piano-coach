# 今夜の作業計画（締切: 2026-10-16、一人 + AI コーディング）

仕様の全体は DESIGN.md にある。今夜はそのうち **§2 の一本道** だけを、確実に最後までつなぐ。
原則は 3 つ。

- 部品を作り込む前に、端から端まで通す。
- 時間を区切り、間に合わないものは潔く切る。
- 最後の 1 時間は、通しリハーサルと **バックアップ動画の録画** に使う。

## 今夜の割り切り（DESIGN.md からの変更点）

| 項目 | 仕様 | 今夜 |
|---|---|---|
| 音符データ | Audiveris（OMR）で PDF から認識する | **Mutopia の MIDI から ScoreModel を作る**（トラック 1 = 右手、トラック 2 = 左手）。PDF をドロップしたら、sha256 で対応する MIDI を引く |
| 曲の構造の解析 | Claude が PDF を読む | そのまま実装する（PDF の画像を Claude に見せる。ここは本物の AI） |
| 運指 | エージェントが設計する（§8.3） | そのまま実装する |
| 保存先 | SQLite | JSON ファイル（`data/`） |
| 演奏後の分析 | DTW と多数の指標 | Realtime Judge の集計だけ（正確さ、extra、miss、タイミングの平均と標準偏差、苦手な小節） |
| TTS | Irodori-TTS-Server | `vendor/Irodori-TTS` の venv で、自前の小さな FastAPI を立てる（`InferenceRuntime` を常駐させる。ポート 8790） |
| 日をまたいだ resume | あり | なし（1 回のデモで完結させる） |

## 優先度

**Must（これがないとデモが成立しない）**
1. 3D の鍵盤と、落ちてくるノーツ（Bloom あり）
2. Web MIDI の入力と、Realtime Judge（wait / play）
3. デモ準備画面（音声の開始、MIDI ポートの選択）
4. Backend の WebSocket と Orchestrator（状態機械）
5. ClaudeBrain（`strict_mcp_config=True` など、§10.2 の設定）と、ヒアリング → 計画 → 課題 → 講評のループ
6. 先生の声（Irodori、文ごとのパイプライン、「弾く」の読み補正）と字幕
7. エージェントによる運指の設計と、ノーツへの運指番号の表示
8. 状態ごとの代行処理（Claude が落ちても止まらない）

**Should（「すげぇ」の核）**
9. ホログラムの手によるお手本（運指 → 手首と指の動き。指くぐりはスローとクローズアップ）
10. 先生オーブ（声に合わせて脈動する）、カメラプリセットの切り替え
11. PDF をドロップしたときの演出（ページが浮かぶ → 音符が粒子になって流れ込む）と、Claude による構造解析の読み上げ
12. 正解時のパーティクルとリムライト

**Could（時間が余ったら）**
13. 楽譜パネル（music21 で MIDI を MusicXML に変換し、Verovio で描く）
14. 3D のロードマップ
15. 応答の再生モード
16. 簡易アレンジ（melody_only、bass_root）、レイテンシのキャリブレーション

**今夜はやらない**: Audiveris、DTW、SQLite、resume、block_chords / rhythm_simple、音域の自動検出

## デモの台本（3 分）

1. メヌエットの PDF をドロップする → 3D の演出が出て、先生が「バッハのメヌエットですね。3 拍子、全部で 32 小節です」と話す。
2. ヒアリング: 「ピアノは初めて」「最初のフレーズを弾きたい」と答える。
3. 計画のステップが出る。裏で運指が設計され、ノーツに番号が灯る。
4. ホログラムの手のお手本。指くぐりの場面で、スローとクローズアップになる。
5. 右手を wait モードで弾く → 講評 → テンポを上げて play モードで弾く → 講評。
6. 「次は左手もいっしょにひいてみよう！」で締める。
